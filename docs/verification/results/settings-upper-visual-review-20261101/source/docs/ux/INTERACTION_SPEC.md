## 1. 读取基线与范围约定

当前以 0.4 产品/架构基线、73 页源清单与 [CUSTOMIZATION_DESIGN](CUSTOMIZATION_DESIGN.md) 为准。八套布局/主题均交付；F10–F14 补齐区域尺寸、背景、配色、组合与恢复。旧研究只作历史资料。

本文的 **MVP** 分两批编码：**核心批次** 为最小宿主、扩展生命周期、默认附带的文件树/阅读编辑/搜索/Git 扩展与多项目闭环；**首版补齐** 为 Pi 默认候选适配扩展（Codex/Claude 首期只留接口）、按需终端扩展、项目快速启动和完整设置。两批共同组成建议首版范围，“首版补齐”仍是设计范围，并非已实现。**后续** 不成为首版依赖。H 组是设计交付物，不增加应用内“设计规范”导航。

阶段与产品 PRD 对齐：核心批次对应 v0.1 核心里程碑，首版补齐对应完整 MVP；产品 M0 专指技术验证，不与页面优先级混用。2026-10-31 用户已确认 Pi 为首版默认候选、Codex/Claude 先留接口；本次整合据此消除旧范围差异，通用组件仍按实际能力呈现。

**最高优先级变更：**2026-10-30 用户补充 Everything is a Plugin 产品方向，覆盖旧研究与旧页面备注。文件树、代码、Git 是默认附带且可暂停、禁用、卸载的扩展；宿主仅提供窗口、布局槽位、项目记录、扩展管理、权限/进程基础设施与数据恢复。Horizon 不实现 Agent 规划循环、工具循环或记忆；D/F 组改为外部 Agent 适配。首版实现 Pi 官方 RPC 与受控策略适配；Codex app-server、Claude Code CLI/官方 SDK 只保留后续接口，不假定共用 ACP。项目启动只能运行用户选定并保存的配置。其他未来页面建议见第 6 节；本轮 F10–F14 已进入源清单。

首装使用雾蓝布局与主题，八套均可安装/切换；布局、主题与个人尺寸配置相互独立。尺寸、延迟、数量上限均为**建议目标**，没有原生性能实测数据。本文新增交互约束使用 `REQ-UXI-`，决策使用 `ADR-UX-`，任务使用 `TASK-UX-`。0.3 将未发布草稿中的 `REQ-UX-*` 一次性改为 `REQ-UXI-*`，避免草稿阶段与产品视觉需求撞号；产品使用 `REQ-UI-001…011`；编号后缀保持不变，后续保持稳定。

## 3. 导航、布局与全局行为

### 3.1 层级与会话

`工作区 → 项目 → 文件/差异标签`；搜索、Git、AI、终端均绑定项目。工作区是本地组织记录；首版每个项目对应一个根目录，项目可以没有 Git 仓库。一个工作区可以有多个项目，首版不扫描嵌套仓库作为额外项目。

项目导航与文件标签是两个独立集合。orbit 的顶部项目标签位于文件标签上层且有“项目”可访问名称；aurora 的底部项目栏不与终端会话混用。其他皮肤即使把导航与树放在同一背景内，也保留项目标题和文件区域边界。相同文件名显示最短可区分的相对目录，悬停或焦点提示完整路径。

项目切换只改变当前上下文，不关闭原项目文件，不弹未保存确认。文档、AI 草稿、Git 提交草稿、树展开与滚动位置按项目保存。后台通知带项目名；不自动把用户切回产生通知的项目。工作区切换也保留原集合会话；真正“关闭项目/工作区/窗口”走第 4 节保护。默认工作区不可删除；删除其他工作区明确将成员项目移至默认工作区，不删除源码。项目首版仅属于一个工作区，可从菜单显式移动；已有记录重复添加只打开，不自动搬组。

跨项目快速打开默认不启用；B03/B04 明示当前项目。A02 用于搜索全部已添加项目。点击文件树或搜索结果打开一个临时预览标签；再次打开另一个文件替换该标签。双击、编辑或显式“保留打开”将其转为普通标签。脏文档永不被临时标签替换。

### 3.2 区域与响应规则

| 区域 | 建议尺寸（CSS px） | 常态与限制 |
| --- | --- | --- |
| 窗口标题 / 全局工具条 | 40–48 高；系统安全区单独计算 | 仅项目名、搜索入口、面板入口与设置；其余进菜单 |
| 项目导航 | 图标栏 56–72 宽；展开列表 176–240 宽 | 宽导航不能与另一个宽项目导航同时常驻 |
| 主侧栏 | 默认 264，最小 220，最大 400 宽 | 文件、搜索、Git、结构互斥；保留各自状态 |
| 文件标签 / 上下文条 | 各 32–40 高 | 溢出横向滚动或列表，不多行挤占代码高度 |
| 代码区 | 目标最小 560 宽、240 高 | 窄于目标时先让辅助区域转浮层；长代码允许水平滚动 |
| AI 面板 | 默认 360，最小 320，最大 520 宽 | 宽度不足转覆盖面板；隐藏不停止请求 |
| 终端 | 默认 240，最小 160 高；不超过可用高度 50% | 高度不足转代码/终端切换视图，不保留不可读代码条 |
| 设置弹窗 | 宽 880、高 640 为上限参考；距窗口边缘 ≥16 | 内容区内部滚动，按钮留可视；窄窗口单列分类选择 |

有效宽度是扣除系统安全区后的内容宽度。不能只看屏幕分辨率。以“代码最小宽度 + 当前面板最小宽度 + 间隙”判断能否并列；默认提示断点为 ≥1280、960–1279、<960，展开项目导航时按实际公式提前切换。

1. 空间不足先折叠项目导航到切换入口，再把 AI 改为覆盖式面板，再把主侧栏改为抽屉；不能挤代码到几百像素后继续并列。
2. <960 时最多一个导航/工具抽屉可见。打开 AI 关闭文件抽屉；打开文件抽屉隐藏 AI，双方草稿不丢。覆盖面板使用模态焦点约束与遮罩，关闭后回到触发按钮。
3. 推荐原生窗口最小 640×480 DIP；200% 缩放下仍允许设置、对话框单列滚动。代码和 diff 属于二维内容，保留水平滚动；按钮与说明不得横向溢出。
4. diff 两栏各不足 360 时自动行内显示；预览两栏不足 360 时切成“源码 / 预览”；用户偏好保留，放宽窗口后恢复。终端打开导致代码不足 240 高时切为“代码 / 终端”，切换不结束进程。
5. 分隔条可拖动，也可键盘调节；拖动中只更新布局，不触发文件重载。双击恢复该面板默认尺寸。F10 提供精确调整和重置入口。

### 3.3 专注模式

进入时保存 `layoutSnapshot`：区域可见性、面板类型、期望尺寸、当前焦点、当前项目与布局修订号；隐藏项目导航、侧栏、AI、终端和非必要状态信息，保留文件标签、代码及可见“退出专注”入口。隐藏不停止服务。

专注期间临时打开搜索/AI 以覆盖面板出现，关闭后仍专注；不改进入前快照。退出时恢复快照，并按当前窗口宽高重新计算有效布局。若用户在 F02 显式修改布局，则把修改合入期望布局，退出使用新值；主题和密度不属于快照。项目切换时加载新项目自身快照，退出不能恢复另一个项目的尺寸。窗口缩窄或扩宽只影响有效布局，不覆写期望尺寸。

### 3.4 快捷键、焦点与平台基线 P0

`Mod` 在 macOS 为 Command，在 Windows 为 Ctrl。默认键位如下；可在 F08 改绑。功能必须同时有可见菜单入口。组合输入进行中不执行 Enter 发送、命令确认、树跳转或自定义快捷键。

| 动作 | 默认键位 / 说明 |
| --- | --- |
| 保存 / 保存全部 | Mod+S / Mod+Alt+S |
| 快速打开 / 命令 | Mod+P / Mod+Shift+P |
| 当前文件查找 / 项目搜索 | Mod+F / Mod+Shift+F |
| 关闭当前文件 | Mod+W；模态已打开时先处理模态，不关闭其背后文件 |
| 前后文件 | Ctrl+Tab / Ctrl+Shift+Tab（两端均 Ctrl） |
| 设置 / 侧栏 | Mod+, / Mod+B |
| 项目切换 / 专注模式 / AI / 终端 | 默认通过命令入口；F08 可绑定，避免抢系统或输入法键 |
| 区域轮换 | F6 / Shift+F6；系统占用时通过“移动焦点”命令替代 |
| 关闭瞬态界面 | Escape 逐层：建议框 → 菜单/弹窗 → 覆盖面板；不会停止后台任务 |

常态焦点顺序：全局工具条 → 项目导航 → 主侧栏 → 文件标签 → 代码工具条与编辑器 → AI（若显示）→ 终端（若显示）→ 状态操作。底部项目栏按实际视觉位置进入顺序，F6 使用区域名称轮换。集合内使用单个 Tab 入口与方向键；不让每一行都进入全页 Tab 顺序。没有正数 `tabindex`。

macOS 使用原生左侧窗口控制、Finder、废纸篓和 Command 符号；Windows 使用右侧窗口控制、资源管理器、回收站和 Ctrl 文案。拖动区域不覆盖按钮。路径来自服务返回的显示值，不在前端擅自改变大小写、分隔符或 Unicode。VoiceOver 与 NVDA 分别验收；文件选择、凭据助手、打开系统应用由原生服务实现。以下页面的“P0”表示完整继承本节，不表示省略平台验收。

## 4. 数据保护与状态公共规则

### 4.1 未保存策略 U0–U5

| 策略 | 适用行为 | 明确结果 |
| --- | --- | --- |
| U0 保留上下文 | 切项目、切面板、关菜单、换主题、进出专注 | 不保存、不丢弃文档；恢复原光标、草稿与选择 |
| U1 关闭保护 | 关闭脏标签、移除项目、关闭工作区、退出应用 | B08 三选：保存、放弃本次编辑、取消；多文件按列表批量处理；保存失败阻止关闭 |
| U2 表单草稿 | 新建项目/连接、提交说明、AI 输入 | 面板隐藏保留；显式取消表单丢草稿前确认；无输入时直接关闭；成功后才清空已提交内容 |
| U3 立即生效设置 | 外观、布局、有效编辑器偏好 | 有效值写入后反馈已保存；非法值不应用；Escape 只关闭，不撤销已生效设置；保留“恢复默认/继承” |
| U4 版本冲突 | 磁盘改变、暂存基线变更、AI 补丁落后 | 拒绝旧版本覆盖；保留用户文档，展示比较/刷新/重算入口；覆盖必须是明确动作 |
| U5 活动任务关闭 | 正在克隆、Git 写操作、AI 任务、终端进程 | 隐藏只关视图；关闭项目/窗口时显示实际任务与停止选项；取消退出留在原处；等待停止确认后再释放 |

未保存用圆点并读出“未保存”；Git 修改用 M/A/D 等文字与名称；外部变化用内联提示。一次操作可同时拥有三者。切项目不弹保存框；重命名、移到废纸篓、放弃 Git 变化遇到脏文档时先解决该文档，不把磁盘更改假装成缓冲区更改。

干净文档遇到外部变化自动重读并保持可映射的光标；脏文档显示“磁盘文件已变化”，提供比较、另存副本、放弃本次编辑并重新载入、明确覆盖磁盘。默认不覆盖。保存失败保持脏标记。自动保存默认关闭；启用后建议停止输入 1 秒再保存，启用瞬间不批量保存已有脏稿，等待下一次编辑或显式保存。输入法组合、外部冲突、只读和任务审核文档暂停自动保存并说明原因。

### 4.2 异步、空态与反馈 S0

所有异步视图至少区分 idle、loading、ready、empty、error、cancelled；写操作另有 pending、succeeded、failed，取消为 `cancelling → cancelled/finished/failed`，不能按下停止就宣称已终止。每个操作绑定 `workspaceId/projectId/requestId`，有写入时携带文档或仓库版本。旧请求回包可进入对应项目缓存，不能覆盖当前显示上下文。

首次加载用局部骨架与明确动作；已有结果刷新时保留结果并标注“正在更新”。失败显示发生位置、简短原因、可执行下一步；详细日志按需展开且脱敏。无进度总量时显示不定进度，不编造百分比。禁用动作必须有可读原因，不能只有灰色图标。

空态提供一个主要动作：无项目→添加项目；无文件→打开文件；无更改→显示干净状态；无搜索结果→调整查询；无连接→设置连接；扩展尚未安装→查看可用扩展。Toast 不承载唯一的错误恢复入口。任务成功用轻提示；影响数据的错误保留在对应区域。屏幕阅读器只播报状态摘要，不逐 token 朗读 AI 或逐行朗读终端。

## 5. 逐页交互定义

每页均继承 P0、S0 与所列 U 策略；以下补充其入口/退出、区域、行为、状态和平台差异。未启用的后续能力从正式 UI 隐藏，不能展示可点击的假成功按钮。

### 6.1 扩展状态语义

| 维度 | 值 | UI/操作约定 |
| --- | --- | --- |
| 安装 | absent / installing / installed / updating / uninstalling / failed | 安装与更新有版本和来源；失败不能激活半包 |
| 策略 | inherit / enabled / disabled，按项目或全局 | 策略控制允许激活；手动暂停不改策略 |
| 运行 | inactive / activating / active / sleeping / pausing / paused / stopping / failed | sleeping 是可自动唤醒；paused 是用户要求暂停，必须显式恢复 |
| 原因 | dependency-missing / permission-needed / incompatible / busy / crash | 原因独立于状态；有可执行修复入口 |

最小宿主保留扩展中心、设置、项目记录、命令入口、通知、草稿恢复导出和归属进程管理；即使卸载所有功能扩展，也能重新安装并恢复工作。功能扩展提供文件树、编辑器、搜索、Git、差异、Agent 适配、终端、项目启动、预览等。功能可独立拆包；服务实现可共用宿主基础设施，但不能以此理由把 UI 变成不可禁用的“大核心”。

项目启动临时启用扩展时记录运行租约和启动前状态；停止后只释放本实例租约。无其他使用者且用户未在运行期间修改策略时，恢复原策略/运行状态；若有共享依赖或人工修改则保留并说明。清理不是全局“全部禁用”。暂停终端或启动扩展前必须停止其拥有的进程；只想收起 UI 使用隐藏面板。终端只显示启动扩展的 pipe 输出时，停用终端可转有界日志，不终止启动组；若进程实际依赖 PTY，则列入依赖停止计划。

### 6.2 外部 Agent 能力边界与证据

首版 Pi 以 `AgentAdapter` 接官方 RPC：runtime→模型连接两层；chat 禁用模型工具/自动资源发现，task 通过受控工具前授权与隔离副本。输入 ack 不等于完成，`agent_settled` 联合失败/中止信息判终态；取消先清队列/授权再 abort。每项目一个任务，全局最多两个由用户显式启动的受管 Pi 实例；资源报告包含组合总量。默认审查 baseline→副本结果；应用回原项目前核对磁盘/编辑版本，dirty buffer 可以作为用户明确选择的快照，不强制先保存。无有效 HEAD 首版只聊天。实际协议与限制见 [Pi 调研](../architecture/PI_AGENT_RESEARCH.md) 和 [接口第 7 节](../architecture/INTERFACES.md)。

以下为后续接口研究，首版不实现 Codex/Claude。2026-10-30 核实的方向：Codex 结构化适配使用 app-server 默认 stdio，按实际 CLI 版本生成/校验 schema；Claude Code 结构化适配优先使用官方 Agent SDK 驱动其现有运行时，CLI `-p` 的 JSON/stream-json 可用于能力较少的场景。普通交互 CLI 走终端扩展。Horizon 适配器不接管两者的规划或工具循环。[Codex App Server](https://learn.chatgpt.com/docs/app-server)、[Claude Agent SDK 概览](https://code.claude.com/docs/en/agent-sdk/overview)、[Claude Code 程序化使用](https://code.claude.com/docs/en/headless)。

Codex 官方说明 app-server 存在线程、轮次、事件和批准请求；会话恢复与轮次中断分别有协议动作。Claude 官方 SDK 有权限/提问回调，只有实际回调到达时才显示 D05；既有权限规则自动处理的动作不会凭空再触发 Horizon 授权。能力由适配器报告并在版本探测后启用，不能把本表视作所有 CLI 版本都具备的保证。[Codex 协议与批准](https://learn.chatgpt.com/docs/app-server#approvals)、[Claude 用户输入](https://code.claude.com/docs/en/agent-sdk/user-input)、[Claude 权限](https://code.claude.com/docs/en/agent-sdk/permissions)。

| 能力 | 结构化适配 | 普通终端模式 |
| --- | --- | --- |
| 消息流 / 操作状态 | 仅消费官方事件；未知事件保留摘要，不猜语义 | 显示原终端内容，不重构工具卡片 |
| 请求授权 / 回答问题 | 协议或 SDK 回调提供什么选项就显示什么 | 在 Agent 自己的终端交互处理 |
| 只读模式 | 仅验证 Agent 有实际限制时显示 | 展示用户启动参数，不能保证只读 |
| 中断 / 结束 | 区分轮次中断、会话结束、进程终止 | 控制键/结束归属进程；不声称精确回滚 |
| 恢复 / 附着 | 分别验证历史恢复和运行附着能力 | 只有官方 CLI 对特定会话支持附着才提供入口 |
| 文件审查 / 恢复 | 文件监听与明确基线；恢复前核对版本 | 同样可观察磁盘变化，但不能证明归因 |

Claude 官方 CLI 已有恢复和特定后台会话附着命令；其版本要求和使用方式由适配器验证。它不等同于任意进程都能接管。[Claude CLI reference](https://code.claude.com/docs/en/cli-reference)。远程附着与这些 Agent 的真实实现均属后续；首版只验收 Pi 的受管启动和历史恢复，不提供任意 TUI 附着。

## 7. 可访问性与低拥挤度验收目标

以 WCAG 2.2 AA 为设计目标：普通文字对比度至少 4.5:1，大字至少 3:1；关键边界、状态图形至少 3:1；交互目标最小 24×24 CSS px。产品舒适密度推荐 32–40 px，高密度推荐 24–28 px，不把密集图标点击区缩到 16 px。焦点不得被固定栏或浮层遮住；200% 文字缩放后操作与说明可用。这是待验证目标，不是已通过认证的声明。[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。

树采用层级、展开与选中语义，方向键导航；标签采用手动激活避免遍历时不断加载文件；模态锁定焦点并在关闭后恢复到触发元素或合理替代点。实现参考 WAI-ARIA APG，产品键位细节由本文及组件文档固定。[Tree View](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/)、[Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)、[Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

- 状态使用文字/形状/图标加颜色：未保存圆点、Git M、失败文本；纯图标按钮提供名称与焦点提示，tooltip 不是唯一名称。
- 焦点环建议 2 px、与邻近色清晰区分；皮肤不移除环。虚拟列表保留活动行 DOM，并报告正确层级/总项数；辅助技术导航时不把当前焦点卸载。
- 减少动效跟随系统且可覆盖；取消位移、弹簧和闪动，用即时状态/淡入替代。普通动效建议 120–180 ms；不能等待动画才响应停止、保存或错误。
- 高密度仅改间距与行高，不减少名称、隐藏错误说明或缩小必要点击区。增大代码字体不强迫导航同倍变宽。
- 常驻入口只保留当前项目必要动作；扩展声明命令与面板入口，不自行加入一排图标。安装扩展不等于自动打开其面板。
- 无焦点陷阱：编辑器提供 Escape 后 Tab 离开提示；终端保留 F6/返回编辑器命令；弹窗允许 Escape 的真实取消语义；Agent 待答卡收起后仍有入口。

关键可复现用例：

1. **导航与未保存：**项目甲修改文件未保存→切乙→打开设置换皮肤→回甲→内容/选区/撤销仍在；关闭甲取消后继续编辑。
2. **布局：**宽窗口打开树、AI、终端→专注→缩到 800 宽→临时搜索→退出专注→保留布局意图且使用单浮层；扩回宽度恢复原面板尺寸。
3. **扩展：**项目甲/乙共用 Git；仅禁用甲→乙继续可用；全局卸载→影响清单列乙；取消无变化；确认后设置和扩展中心仍可用。
4. **Agent：**以固定 Pi 版本发送测试任务→受控工具请求→拒绝→中断→审查副本结果；Codex/Claude 只检查接口设计；终端模式不展示虚假结构化能力。
5. **启动：**只扫描 package.json 不执行→用户保存两个服务方案→启动一次→一个就绪、一个失败→准确展示并回收本实例拥有资源；未保存文件可选择按磁盘运行。
6. **恢复：**编辑器扩展崩溃→宿主导出恢复稿；终端扩展停止超时→仍可看归属进程并再次停止；不能报告已释放。

以上属于验收设计，尚未运行。原型可验证状态与导航；真实文件保护、Git、Agent、扩展释放、进程结束、性能和读屏必须在桌面实现上验证。
