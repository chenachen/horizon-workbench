## candidate7 源码修复及验证

这些修改发生在 candidate6 原生操作之后，**尚未打包或完成原生 GUI 复测**。

- 回收站改用 macOS `NSFileManager`；冲突删除、未跟踪放弃和克隆残留清理共用同一路径，仍是可恢复的回收站操作。
- Git 忙碌弹窗内直接提供 Stop，调用原任务取消句柄；默认焦点落在取消按钮。
- Git 错误只在当前相关面板显示一次；已识别错误用简短原因，Git 原文可展开查看。
- 引用比较先关闭分支弹窗，再打开结果；远端 symbolic HEAD 不作为分支列出，蓝底仅当前分支。
- 历史长标题换行；历史删除文件隐藏“打开文件”；空差异居中；并排分隔线铺满阅读区；mode 元数据不冒充代码行；代码字体遵循设置。
- 冲突区补齐 40px 文件标签层与行号；合并提示明确可以解决、暂存、提交。
- 未跟踪差异生成正确 hunk，新增行从 1 开始，后续页保持连续行号。
- 克隆预检拒绝不再显示“本次残留”清理操作或“连接远端”状态；移除重复标题。真正的克隆残留确认直接替换当前弹窗内表单，保留取消、具体路径和危险操作，不再开启第二个原生 dialog。

4 项针对性服务回归通过：原生回收站、差异分页行号、远端 symbolic HEAD 过滤、克隆归属保护。回收站用真实 macOS 文件管理调用，0.56 秒完成测试。TypeScript 通过。原始日志及源码哈希见 `results/git-candidate7-source/`；未把历史 18 项测试冒称为本次全量重跑。
